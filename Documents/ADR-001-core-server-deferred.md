# ADR-001. C++ 코어서버 보류 — FastAPI 단일 서버 구성

- **상태**: Accepted
- **결정일**: 2026-07-26
- **적용 범위**: 프로젝트 전체 (UE5 클라이언트 / Server_Core / backend_server)
- **관련 문서**: `Documents/타임머신 AR 프로젝트 통합 문서.txt`, `Shared/include/Packets.h`

---

## 1. 결정

**C++ 코어서버(`Server_Core/`)를 당분간 사용하지 않는다.**
UE5 클라이언트는 Python FastAPI(`backend_server/`)에 HTTP로 직접 연결한다.

**사용자 간 동기화가 실제로 필요해지는 시점에 코어서버를 다시 투입한다.**
따라서 이는 *폐기(deprecated)* 가 아니라 *보류(deferred)* 이며, 기존 C++ 자산과
패킷 명세는 그대로 보존한다.

## 2. 근거

- 현재 우선순위인 AI 도슨트·전시물 조회·로그 적재는 전부 **요청-응답형**이라
  상태 동기화가 필요 없다. 코어서버를 경유하면 홉만 하나 늘어난다.
- 1인 관람 시나리오에서는 브로드캐스트할 상대가 없으므로 30Hz 루프 자체가 무의미하다.
- 서버를 하나로 줄이면 통합 지점이 줄어 도슨트 기능의 완성도를 먼저 확보할 수 있다.

## 3. 구분 — 지금 무엇을 하고, 무엇을 미루는가

### 3.1 지금 (FastAPI 직결, 이번 단계 범위)

| 기능 | 방식 | 상태 |
|---|---|---|
| AI 도슨트 질의 | `POST /docent/ask` | 이번 브랜치에서 구현 |
| 공룡 종 목록 | `GET /dinosaurs` | 구현 완료 |
| 전시물 + POI 조회 | `GET /exhibits/{id}` | 구현 완료 |
| 헬스체크 | `GET /health` | 구현 완료 |
| 3D 에셋 URL 제공 | HTTP | 미착수 |
| 관람 로그 적재 (`view_logs`) | HTTP | 미착수 |
| TTS 음성 합성 | HTTP | 미착수 |

→ 통합 문서의 **"웹 백엔드 서버(컨트롤 플레인)"** 역할 전부. 이번 결정으로 **유일한 서버**가 된다.

### 3.2 나중 (코어서버 부활 시)

| 기능 | 패킷 | 보류 사유 |
|---|---|---|
| 세션 입장/퇴장 | `PKT_JOIN(0x01)` / `PKT_LEAVE(0x02)` | 다중 사용자 전제 |
| 아바타 위치·회전 동기화 30Hz | `PKT_TRANSFORM(0x03)` | 동기화 상대 없음 |
| 시대 변경 **전체 동기화** | `PKT_ERA_CHANGE(0x04)` `SyncMode=1` | 다중 사용자 전제 |
| 연결 유지 / RTT 측정 | `PKT_HEARTBEAT(0x05)` | UDP 세션 전제 |
| RUDP 수신 확인 | `PKT_ACK(0x07)` | UDP 전송계층 전제 |
| 세션 현황 브로드캐스트 | `PKT_SERVER_STATE(0x08)` | 다중 사용자 전제 |
| 주변 유저 집계 브로드캐스트 | `PKT_WORLD_STATE(0x09)` | 다중 사용자 전제 |
| Dead Reckoning 보간 | — | 원격 아바타 없음 |
| 50 CCU 부하 테스트 | — | 위 항목들에 의존 |

### 3.3 이번 결정으로 UE5 클라이언트로 이동하는 로직

| 항목 | 기존 (코어서버) | 변경 후 |
|---|---|---|
| AI 도슨트 트리거 | `PKT_AI_TRIGGER(0x06)` C→S→BE | **UE5가 `POST /docent/ask` 직접 호출** |
| Gaze 2초 임계 판정 | `FAiTriggerPacket.GazeDuration >= 2.0f` 서버 검증 | **UE5 클라이언트에서 판정 후 호출** |
| 시대 변경 **개별 모드** | `PKT_ERA_CHANGE` `SyncMode=0` | **UE5 로컬 처리** (서버 왕복 불필요) |

> 즉 9개 패킷 타입 중 **`0x06` 하나만 HTTP로 대체**되고, 나머지 8개는 전부 순수 동기화용이다.
> 구분선이 깨끗하므로 나중에 코어서버를 되살릴 때 이번 작업과 충돌하지 않는다.

## 4. 영향 — 갱신이 필요한 기존 계획

통합 문서의 아래 항목은 이 결정과 **모순되므로 팀 합의 후 갱신**이 필요하다.

### 4.1 로드맵 (통합 문서 §5)

| 주차 | 원래 계획 | 이번 결정 반영 |
|---|---|---|
| W3 | C++ IOCP 스레드 풀, RUDP 기초 | **보류** |
| W4 | FastAPI 백엔드 및 LLM 연동 | **진행 — 현재 위치** |
| W5 | 세션 관리/브로드캐스팅, 부하 테스트 | **보류** |
| W7 | UE5에 RUDP 클라이언트 이식, 아바타 렌더링 | **보류** |
| W9 | AI 도슨트 API 연동, 자막·TTS | **유지** (HTTP 직결로 변경) |
| W10 | Dead Reckoning 적용 | **보류** |
| W11 | 50 CCU 테스트 | **보류** (72 FPS 최적화는 유지) |

### 4.2 마일스톤 검수 기준 (통합 문서 §5-2) — **재정의 필요**

| 마일스톤 | 기존 검수 기준 | 문제 |
|---|---|---|
| M2 (W5) | 더미 클라이언트 50개 접속 시 지연 50ms 이하 | 코어서버 부재로 **측정 불가** |
| M3 (W9) | 서버 위치 동기화 및 AI 도슨트 정상 응답 | 위치 동기화 부분 **무효** |
| M4 (W12) | 네트워크 단절 시 데드레코닝 정상 작동 | **무효** |

→ 대체 기준 제안: M2를 "FastAPI 도슨트 응답 ≤2s(KPI 유지) + Swagger 계약 확정",
M3를 "Quest 3에서 POI 응시 → 도슨트 응답·TTS 출력", M4를 "72 FPS 유지 + 오프라인 폴백 동작"으로.
**확정은 팀 논의 필요.**

### 4.3 팀 분업 (통합 문서 §3-2)

팀원 B의 담당 파트(IOCP·RUDP·세션·브로드캐스팅·DR·부하테스트)가 통째로 보류 대상이다.
역할 재배치는 이 문서의 범위 밖이며 **팀 논의가 필요하다.**

### 4.4 기획 문구

기획서의 **핵심 가치** "다중 사용자 간 초저지연 동기화 체험" 과
**차별성** "C++ 저수준 네트워크" 항목은 현재 구성과 불일치한다. 포트폴리오 서술을
수정할지, 아니면 후반에 코어서버를 복귀시켜 원안을 지킬지 결정이 필요하다.

## 5. C++ 자산 보존 방침

**삭제하지 않는다.** 현재 `Server_Core/` + `Shared/include/Packets.h` 에 약 2,672줄,
12개 커밋이 축적되어 있으며 최신 커밋은 `feat: Core_Server demo complete` 이다.

- `Server_Core/` — 현 상태 동결(frozen). 신규 기능 추가는 하지 않되 삭제도 하지 않음.
- `Shared/include/Packets.h` — **유지**. 부활 시점의 프로토콜 계약이자 설계 기록.
- 빌드 산출물(`cmake-build-debug/`)은 커밋에서 제외되어야 한다(별도 정리 대상).

## 6. 코어서버를 다시 꺼내는 조건 (Trigger)

아래 중 **하나라도** 참이 되면 이 ADR을 재검토한다.

1. 같은 전시 공간에서 **2인 이상이 서로의 아바타를 봐야** 하는 요구가 확정될 때
2. 타임 슬라이더 **전체 동기화 모드**(`SyncMode=1`)를 실제로 쓰기로 할 때
3. HTTP 폴링으로는 감당 안 되는 **실시간 상태 공유**가 필요해질 때
4. 포트폴리오 관점에서 **C++ 저수준 네트워크 구현을 증명**해야 한다고 팀이 판단할 때

## 7. 후속 확인 필요 항목

- **ID 타입 불일치**: `FAiTriggerPacket` 은 `ObjectId`/`LocationId` 를 `uint32_t` 로 정의하지만,
  DB(`pois.id`, `exhibits.id`)는 `UUID` 다. HTTP 직결에서는 UE5가 UUID 문자열을 그대로 보내면 되어
  문제가 없으나, **코어서버 부활 시 이 불일치를 해소해야 한다**(UUID↔정수 매핑 테이블 또는 패킷 스키마 변경).
- `EraId` 정의에 백악기=4 가 이미 있으나, 현재 공룡 박물관 DB 스키마에는 시대 코드 컬럼이 없다
  (`dinosaurs.period` 는 `VARCHAR`). 타임 슬라이더 구현 시 매핑 규칙 필요.
- 인증 부재 상태로 FastAPI가 외부에 직접 노출되므로, Quest 3 실기 테스트 전
  최소한의 접근 제어(네트워크 레벨 포함) 검토 필요.

## 1. 사용자 요청과 구현 목표

현재 AR 화면에 표시된 아르켈론 에셋을 클릭/터치하면, 제공된 완성 시안과 같은 세로형 전체 화면 정보창이 열리도록 구현한다. 기본 탭은 소개이며, 소개 / 특징 / 서식 / 발견의 네 탭이 실제로 작동해야 한다. 기존 Unreal Engine 5.4 C++/UMG 프로젝트 안에서 구현한다.

핵심은 짙은 해양 박물관 배경, 크게 배치된 아르켈론 대표 이미지, 청록 발광 테두리, 탭별 설명과 요약 카드 4개, 렉시 도슨트 CTA, 하단 내비게이션을 시안과 가깝게 재현하는 것이다. 완성 시안을 통째로 배경에 붙이고 투명 버튼만 얹는 방식은 사용하지 않는다. 텍스트와 버튼은 실제 UMG 위젯으로 구성한다.

이 문서의 계획을 실행하라. 먼저 현재 변경사항과 Blueprint 연결을 확인하고, 기존 작업을 보존하면서 코드·UMG·데이터 에셋·이미지 임포트까지 완료하라. 확인하지 못한 에디터/실기기 결과를 완료했다고 보고하지 말라.

## 4. 화면 배치와 스타일

완성 시안은 약 9:16 세로 화면이다. 다음 비율은 시안에서 읽은 근사 시작값이며 최종적으로 캡처와 비교하여 조정한다.

1. 전체 배경: 깊은 남색 해양 전시관 이미지와 어두운 오버레이. 전용 배경 소스가 제공되지 않았으므로 프로젝트 내 기존 배경을 먼저 조사한다. 적절한 소스가 없다면 남색 해양 질감과 그라데이션으로 임시 구성하고 시안과의 차이를 보고한다. 텍스트가 박힌 완성 화면 전체를 배경으로 쓰지 않는다.
2. 상단 약 2~8%: 왼쪽 원형 뒤로 버튼, 중앙 '아르켈론 전시존 / 고대 바다의 거대 거북' 위치 배지, 오른쪽 원형 메뉴 버튼.
3. 히어로 약 8~35%: 왼쪽·중앙에 큰 아르켈론. 오른쪽에 '아르켈론', 이탤릭 `Archelon`, '해양 파충류' 청록 배지, '백악기 후기' 주황 배지. 이미지 비율을 유지하고 중요한 얼굴/지느러미가 잘리지 않게 한다.
4. 약 35~41%: 소개/특징/서식/발견 4등분 탭 바. 모든 탭에 아이콘을 표시한다.
5. 약 42~77%: 둥근 본문 패널. 상단 짧은 청록 선, 제목, 본문, 오른쪽 상단의 은은한 관련 삽화, 아래 4개 요약 카드. 삽화가 본문 가독성을 떨어뜨리지 않도록 마스크/그라데이션 또는 별도 영역을 사용한다.
6. 약 79~88%: 렉시 이미지가 왼쪽에서 살짝 돌출되는 CTA, 중앙 2줄 문구, 오른쪽 화살표.
7. 약 89~98%: 내비게이션 / AR 스캔 / 도슨트의 하단 바. 이 정보 화면에서는 AR 스캔이 활성화되어 있다.

시작 스타일 값: 배경 `#061523`, 패널 `#0A2034` 계열, 강조 `#50DAFF`, 본문 `#E8F3FC`, 보조 글자 `#B1C6DB`, 주황 아이콘 `#FFB44D`. 이는 추정 팔레트이므로 원본 시안과 대조해 조정한다. 패널은 반투명 남색, 가는 청록 테두리, 절제된 외곽 빛으로 표현한다. 실제 픽셀 추출값으로 주장하지 않는다.

## 6. 데이터와 위젯 변경 설계

기존 공용 위젯을 확장하되 다른 종의 스타일이 의도치 않게 변경되지 않도록 아르켈론용 스킨 옵션 또는 기존 C++ 기반의 전용 WBP 파생을 사용한다. 실제 Blueprint 재사용 관계를 조사한 뒤 변경량이 작은 쪽으로 결정한다.

`FDinoTab`에 추가할 필드 제안:

```cpp
// 실제 선언 시 기존 스타일에 맞는 UPROPERTY(EditAnywhere, BlueprintReadOnly)를 붙인다.
TArray<FDinoStat> Stats;
FText DocentPrompt; // CTA 보조 문구
```

현재 탭 Stats가 비어 있으면 기존 `UDinoInfoData::Stats`로 fallback한다. CTA도 탭 문구가 없으면 종의 공통 안내문을 쓴다. `ApplyTabContent()`에서 제목·본문·삽화·Stats·CTA를 한 번에 갱신하고, 공통 Stats를 나중에 다시 덮어쓰는 기존 `ApplyInfo()`의 호출 순서를 정리한다. `Tabs`가 없는 구형 에셋의 `IntroText` fallback도 보존한다.

상단 전시존 이름·설명과 화면 배경은 필요한 경우 선택 필드로 추가한다. 기존 `DietTag`는 실제로 분류 태그 용도로도 쓰이므로 이번 작업에서 일괄 이름 변경하지 않고 아르켈론 값에 '해양 파충류'를 넣을 수 있다.

기존 `BindWidget`/`BindWidgetOptional` 이름을 먼저 확인한다. NameKoText, NameSciText, HeroImage, TabHeading, IntroLabel, TabImage, TabBar, StatBox, CardPanel, ContentScroll, CloseButton, AskDocentButton, DocentCta 등 C++ 연결을 유지하고 새 이름은 헤더와 WBP를 동시에 맞춘다. 구형 FullscreenButton은 새로운 화면에 필요하지 않으면 숨기되 다른 종의 기능을 깨뜨리지 않는다.

## 7. 실제 동작 계약

- AR의 아르켈론 터치/PC 클릭 → 기존 OnDinoClicked 경로 → 해당 DA로 ShowFor → 소개 탭을 선택해 화면 하나만 연다. 재터치로 중복 위젯을 쌓지 않는다.
- 탭 전환 → 헤더/히어로/하단 바는 유지하고 해당 본문·삽화·카드·CTA 보조 문구만 변경한다. 중앙 스크롤은 탭 변경 시 맨 위로 이동한다.
- 뒤로 버튼 또는 Android 뒤로 → 카드 닫기 → 직전 AR 화면과 입력 복원. 마커 세션/모델을 새로 만들지 않는다.
- CTA/하단 도슨트 → 현재 아르켈론 ExhibitKey를 기존 도슨트 열기 경로에 전달한다. 카드를 숨기거나 적절한 Z-order로 전환해 채팅을 실제로 사용할 수 있게 한다. 단순 CTA 클릭만으로 서버에 질문을 자동 전송할 필요는 없다.
- 도슨트에서 돌아오면 같은 아르켈론/선택 탭을 복원하는 것을 기본 정책으로 한다. 외부 AR에서 새로 여는 경우 소개로 시작한다.
- 하단 AR 스캔 → 정보창을 닫고 기존 스캔 화면으로 복귀. 내비게이션 → 기존 내비게이션 화면/동작 재사용. 새 길찾기 시스템을 만들지 않는다.
- 메뉴 → 기존 메뉴 동작 재사용. 기존 경로가 없으면 최소 메뉴(정보창 닫기/AR로 돌아가기, 도슨트 열기)를 구현하여 무반응 버튼을 남기지 않는다.
- 카드 열림 중 뒤쪽 AR 액터 클릭은 차단한다. 닫힌 뒤에는 다시 터치가 통과해야 한다.
- 기존 스와이프 닫기는 전체화면 UI의 세로 스크롤과 충돌 여부를 확인한다. 이 스킨에서는 기본 비활성화하거나 헤더 전용 제스처로 제한하여 본문 읽기가 갑자기 닫기로 처리되지 않게 한다.

## 8. 이미지 가공·임포트 계획

1. 원본 7개 크기/알파/여백 검사. `references`는 수정하지 않는다.
2. (1)에서 Hero, (7)에서 렉시/지도/골격/특징 삽화, (6)에서 적절한 무문자 패널을 별도 PNG로 준비한다. 시트에 인접한 요소가 겹친 영역은 무리하게 자동 크롭하지 않는다.
3. 생성 이미지의 글자와 도형은 깨짐이 있을 수 있다. 본문·제목·배지 문구·탭 라벨은 FText로 다시 쓰고 이미지에 구워진 글자와 중복되지 않게 한다. 패널은 UMG 브러시/9-slice로, 단순 선형 아이콘은 기존 선명한 아이콘 에셋이 있으면 재사용한다.
4. 권장 파생 경로: `docs/ai-handoff/inbox/archelon_info/`, UE 임포트 경로: `/Game/UI/DinoCard/ArchelonSkin/`. 파일명 예: `T_ArchelonHero`, `T_RexyCTA`, `T_HabitatMap`, `T_DiscoverySkeleton`, `T_FeatureIllustration`, `T_InfoPanel`.
5. 크롭 결과와 원본 좌표/파일 매핑을 manifest에 남긴다. UI 텍스처 설정과 cook 포함은 기존 import 스크립트 방식을 참고해 검증한다. 동적 문자열 로딩만 사용하는 리소스는 패키징 누락을 막는다.
6. 한국어 폰트의 실제 에셋/패키징을 확인한다. 모든 위젯에 동일 폰트 계열과 굵기 체계를 적용한다. 광택/발광은 가능한 한 브러시나 텍스처로 처리하고 모바일에서 과도한 블러와 Tick 기반 효과를 피한다.

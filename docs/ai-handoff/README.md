# AI 핸드오프 규약 (Claude ↔ ChatGPT)

Claude 는 이 저장소를 직접 읽고 쓴다. ChatGPT 는 못 한다. 둘 사이에 직접
통로도 없다. **사람이 유일한 전달자다.** 이 폴더는 그 전달을 규칙화한 것이다.

## 역할

| 주체 | 할 수 있는 것 | 할 수 없는 것 |
|---|---|---|
| Claude | 저장소 읽기·쓰기, 파일 검증, 빌드·설치, 실기기 캡처 | 이미지 생성, ChatGPT 세션 접근 |
| ChatGPT | 이미지 생성 | 저장소 접근, 파일 저장 |
| 사람 | 양쪽 사이 복사·붙여넣기, 파일 저장 | — |

## 흐름

1. Claude 가 `BOARD.md` 에 요청(`REQ-00N`)을 쓴다. 파일명·크기·형식까지 못 박는다.
2. 사람이 요청 안의 **[GPT 프롬프트]** 블록을 통째로 ChatGPT 에 붙여넣는다.
3. ChatGPT 가 이미지를 만든다.
4. 사람이 결과 파일을 **지정된 파일명 그대로** `docs/ai-handoff/inbox/` 에 저장한다.
5. 사람이 ChatGPT 의 **[응답]** 블록을 `BOARD.md` 의 해당 요청 아래에 붙여넣는다.
6. Claude 가 실제 파일을 검증한다. 통과하면 `ACCEPTED`, 아니면 `REJECTED` +
   재요청을 쓴다.

## 규칙

- **파일명을 바꾸지 않는다.** Claude 가 지정한 이름 그대로 저장한다.
  이름이 다르면 Claude 가 못 찾는다.
- **한 번에 요청 하나.** 번호는 `REQ-001` 부터 순서대로.
- **"완료" 는 주장이지 증거가 아니다.** Claude 는 응답 블록을 믿지 않고
  파일의 실제 크기·형식·알파 채널을 직접 확인한다.
- **상태는 Claude 만 바꾼다.** 사람과 GPT 는 응답 블록만 추가한다.
- 상태값: `OPEN`(요청됨) / `DELIVERED`(파일 도착) / `ACCEPTED`(검증 통과) /
  `REJECTED`(반려, 사유는 Claude 가 적음)

## 왜 이 폴더에 두는가

`.gitignore` 가 `Build/` 와 `TimeMachineAR/Asset/` 를 제외한다. 원본 이미지를
거기 두면 커밋되지 않아 팀원 클론에서 사라진다. 그래서 원본은 추적되는
`docs/ai-handoff/inbox/` 에 두고, 실제 빌드 경로
(`TimeMachineAR/Build/Android/res/`)에는 스크립트로 생성해 넣는다.

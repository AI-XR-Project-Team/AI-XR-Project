## 1. 목표와 보존 범위

기존 AR 전용 마커를 인식하면 회중시계가 자동으로 준비된다. 사용자가 시계를 위로 스와이프해 던져 목표에 맞히면 시계와 바늘이 회전하고 NS_ActiveAtom 기반 빛 궤도가 생긴다. NS_Worm-Hole 기반 시간의 문이 확장되며 잠시 시야를 흐리고 기존 아르켈론 스태틱 메시가 나타난다. 효과가 사라지면 기존 터치 정보창 기능으로 돌아간다.

자동인식은 시계를 준비하는 단계까지다. 사용자 투척 없이 연출을 자동 재생하지 않는다. 디버그 자동 재생은 별도 개발 기능으로만 허용한다.

- 현재 UI 배치·스타일, 정보창, 도슨트, 내비게이션, 카메라·촬영 버튼을 유지한다. 참고 이미지의 UI를 새로 만들지 않는다.
- 이미 완성된 기능을 과거 버전으로 되돌리지 않는다. 최소한의 이벤트 연결·입력 분기·등장 지연만 허용한다.
- 아르켈론은 기존 StaticMesh를 쓴다. 새 리깅·헤엄치는 애니메이션·모델 교체는 범위 밖이다.
- 회중시계 원본과 FreeNiagaraPack 원본은 보존한다. 프로젝트 전용 파생 에셋으로 작업한다.
- 원본 이미지의 손, 박물관 배경, UI 프레임을 화면에 합성하지 않는다. 실제 카메라 영상이 배경이다.
- 새 종 전체에 강제 적용하지 않는다. 기존 등록 정보로 아르켈론을 식별하고 종별로 기능을 켤 수 있게 한다.
- 원격 push·머지는 이번 지침서만으로 승인된 것으로 해석하지 않는다. 구현과 검증 결과를 먼저 정리한다.

## 4. 먼저 통과해야 할 시계 품질 기준

1. 세 모델을 별도로 임포트하고 앞·뒤·옆에서 검수한다. 본체 문자판에 이미 바늘이 메시/텍스처로 포함됐는지 확인한다. 중복 바늘은 원본을 보존한 파생 에셋에서 해결한다.
2. Meshy가 각 부품을 독립 생성했으므로 공통 축·단위·비율을 가정하지 않는다. 문자판 중앙과 법선 방향을 기준으로 바늘을 정렬한다.
3. 바늘의 자체 중앙이 아닌 실제 회전 연결점에 SceneComponent 피벗을 둔다. 바늘 mesh를 그 아래 오프셋해서 회전시킨다. 회전 시 궤도를 공전하거나 중심이 흔들리면 실패다.
4. 바늘 두 개의 깊이를 소량 분리한다. 문자판과 z-fighting, 관통, 그림자 얼룩이 없어야 한다. 회전축은 임의의 World Z가 아니라 문자판 법선을 쓴다.
5. Base Color는 색상 텍스처, metallic/roughness는 선형 마스크, normal은 노멀 설정으로 임포트한다. 녹색 채널 반전은 실제 조명 검수 후 결정한다.
6. Nanite나 Lumen에 의존하지 않는다. 원본의 실루엣·문자판을 유지하는 모바일용 LOD/재질을 만든다. 불필요한 내부 면과 고밀도 바늘을 확인한다.
7. 시작 예산: 시계 전체 LOD0 10k~20k triangles 이내를 목표, 본체 2K, 바늘 512~1K 텍스처를 우선 검토한다. 이는 초기 예산이며 화면 품질과 실기기 측정으로 조정하고 실제 수치를 보고한다.
8. 금속이 카메라 배경 위에서 검게 죽지 않게 모바일 조명 조건을 검수한다. 금속 전체를 강한 Emissive로 바꾸지 않는다. 필요한 경우 시계만 영향을 받는 제한적인 보조 표현을 쓴다.

## 5. 미술 방향과 연출 시간표

핵심은 ‘황금 시계가 차가운 시간 에너지를 열어 아르켈론을 불러온다’이다. 무지개 입자·과도한 번쩍임·화면 전체 백색 날림을 피한다. UI는 항상 읽혀야 한다.

권장 색상: 청백 #DDF5FF, 전기 파랑 #4BA3FF, 보조 청록 #58D8E8, 시계 금색 #D9AA57. 이 HEX는 미술 기준 sRGB이며 Unreal 선형 색상 입력으로 옮길 때 변환을 고려한다.

다음 시간은 명중 시점 t=0 기준 시작값이다. 커브/DataAsset로 조정 가능하게 한다.

- 준비: 기존 하단 버튼 바로 위의 빈 카메라 영역에 시계가 약 0.3초에 걸쳐 부드럽게 등장. 짧은 미세 부유, 과한 흔들림 없음. 화면 폭 약 18~24%를 출발점으로 기기별 확인.
- 투척: 유효 스와이프 후 약 0.55~0.85초. 시계 크기와 원근이 자연스럽게 변하는 포물선. 끝에서 과도한 튕김 없음.
- 0.00~0.18초: 작은 청백 명중 섬광, 시계가 목표 앞에 멈추고 회전 가속.
- 0.12~1.10초: ActiveAtom 궤도가 시계 주변에 형성. 바늘은 본체보다 빠르게 회전하고 속도 차이를 둔다. 빠른 바늘이 깜빡이는 선으로만 보이지 않게 조정.
- 0.65~2.00초: Worm-Hole이 작은 원에서 목표를 감싸는 크기로 확장. 골드 포인트를 청색 소용돌이에 소량 유지.
- 1.30~1.85초: 짧은 흐림/반투명 전환이 정점. 카메라 배경에만 적용하고 UI는 선명하게 유지.
- 1.60~2.70초: 기존 아르켈론이 시간의 문 속에서 나타남. 시계는 문 안으로 수렴하며 사라짐. 노출 시점과 포털 크기를 맞춰 갑작스러운 팝인 방지.
- 2.70~3.50초: 시간의 문과 잔광이 부드럽게 소멸. 모델이 가려지지 않는 즉시 정상 터치로 복귀.

연출 길이보다 단계의 연결과 감속이 중요하다. 각 단계가 딱 끊기는 Delay 나열 대신 정규화 시간과 커브를 쓴다. 저프레임에서도 동일한 순서로 완료되어야 한다.

## 6. Niagara 파생 효과 제작

권장 경로: /Game/TimeReveal/FX/NS_WatchOrbit, NS_TimePortal. 원본을 복제하고 공유 material까지 변경할 경우 관련 material도 복제한다. 모든 원본 효과가 함께 변색되는 수정은 금지.

ActiveAtom:
- 핵심 원형 궤도는 유지하되 중앙의 강한 빛이 시계 문자판을 가리지 않게 줄인다.
- 시계에 붙는 공간 기준과 전체 크기를 확인한다. Local Space를 일괄 변경하지 말고 각 emitter별 의도를 확인한다.
- 색상, 밝기, 궤도 크기, 회전 속도, 밀도, 종료 페이드를 조정한다. 가능하면 2~3개 읽히는 궤도를 중심으로 정리한다.

Worm-Hole:
- 안개가 아닌 시간의 문으로 연출한다. 카메라 방향에 맞는 문 평면을 처음에 정하고 회전 안정성을 유지한다.
- 중심이 검은 원판처럼 아르켈론을 가리지 않도록 재질과 알파를 확인한다. 모델이 문 앞/뒤 어느 위치에서 드러나는지 깊이 관계를 설계한다.
- 메시 bounds를 참고하되 긴 지느러미 전체를 무조건 덮는 거대한 화면 이펙트를 만들지 않는다.
- 실제 카메라의 박물관 깊이/화석을 GPU scene depth로 읽을 수 있다고 가정하지 않는다. 필요한 충돌·깊이 의존 기능은 독립적으로 검증하거나 제거한다.

권장 공개 파라미터 계약(원본에 있다고 가정하지 말 것):
User.PrimaryColor, User.SecondaryColor, User.Intensity, User.RadiusScale, User.SpeedScale, User.DensityScale, User.Fade.
종류·기본값·단위를 문서화하고 Niagara 그래프/renderer/material까지 실제 연결한다. C++에서 변수 이름만 설정하고 효과에 반영되지 않는 구현은 실패다. 곡선 모듈이 매 틱 색상을 덮어쓰는지 확인한다.

활성 emitter의 Sim Target, 사용 renderer, 고정 bounds, loop/lifetime, depth collision, GPU 전용 모듈을 에디터에서 조사한다. Android에서 부적합한 emitter는 가능한 CPU/저비용 버전으로 재작성하거나 대체한다. GPU를 CPU로 설정만 바꿔 해결됐다고 하지 않는다. 실제 compile/cook/실행이 기준이다.

블러는 별도 기능이다. 웜홀 자체가 배경을 흐리게 한다고 주장하지 않는다. 모바일 카메라 합성 경로에서 제한된 별도 패스가 가능한지 먼저 확인한다. 불가능하면 얇은 반투명 청백 베일+소용돌이로 대체하고 ‘실제 블러가 아닌 대체’라고 보고한다. 스캔 루트/기존 정보창 재질을 전역 변경하지 않는다.

## 7. 코드 구조와 입력 계약

권장 구성은 별도 ATimeWatchActor(본체와 바늘), UTimeRevealComponent(상태·수명), UTimeRevealProfile(DataAsset: 에셋·커브·색·시간·배치), 기존 Overlay/TrackingManager의 작은 연결부다. 실제 저장소 규칙에 맞춰 이름을 조정하되 기능 소유자는 한 곳이어야 한다.

상태: Idle → Ready → Throwing → Impact → Portal → Revealing → Complete. Cancelled 및 재시도 경로 포함.

- 오직 유효한 아르켈론 AR 마커에서 진입한다. 범용 OnMarkerFound에 무조건 반응하거나 fallback 종만 보고 내비게이션 마커를 오인하지 않는다. 실제 Registry 매핑을 확인한다.
- Ready 전에 Flesh/Bone 가시성·충돌 원래 값을 저장한다. 새 연출에 필요한 부분만 일시 조정하고 성공/취소 시 올바르게 복구한다. 기존 Alpha 재질이 불투명이라면 등장 전에는 명시적으로 숨겨 조기 노출을 막는다.
- 시계가 준비된 동안에만 시계 주변에서 시작하는 드래그를 받는다. 전체 화면 투명 위젯으로 기존 버튼 입력을 가로채지 않는다.
- 한 손가락 pointer만 소유한다. DPI/화면 크기로 정규화한 최소 이동거리와 방향 조건을 쓴다. UI에서 시작한 드래그, 짧은 탭, 멀티터치는 투척하지 않는다.
- Ready의 시계는 카메라 기준 배치. 투척 시작 시 world 좌표로 전환하여 이후 손/카메라를 따라붙지 않게 한다.
- 명중은 실제 화석의 자동 영상 분할이 아니라 AR 앵커 기준 가상 타깃이다. 모델의 원점이 아닌 실제 bounds와 MeshTransform을 반영한다.
- 곡선 기반 궤적과 제한된 목표 보정으로 쉽게 맞힐 수 있게 한다. 타깃이 화면 밖이거나 추적 불안정하면 투척을 받지 않거나 Ready로 복구한다. 빗나가면 영구 정지하지 않고 짧게 회수/재준비한다.
- 투척 터치가 기존 HandleTapped로 전달되어 정보창이 뜨지 않아야 한다. 완료 뒤 정상 터치는 다시 열려야 한다.
- 기존 응시 StartReveal 및 Blueprint의 조기 표시를 새 상태 소유자가 통제한다. 전역적으로 기존 기능을 삭제하지 않는다.
- TrackingManager가 호출하는 StopScan은 ‘마커 인식 완료’에도 발생하므로 이를 곧바로 사용자의 취소로 해석하지 않는다. 실제 AR 닫기/모드 이탈/세션 종료와 구분한다.
- 재인식 중복 방지 키는 현재 세션+타깃. ClearOverlay/새 스캔 후에는 다시 재생 가능해야 한다.
- 추적 잠깐 끊김과 ARPin 소실을 구분한다. 짧은 중단은 마지막 유효 pose 유지/진행 정지, 장기 소실은 안전 취소. 시간 기준을 설정값으로 두고 카메라 원점으로 순간 이동하지 않게 한다.
- AR 닫기·도슨트/내비 전환·앱 백그라운드·액터 파괴 시 delegate/timer/Niagara/시계/입력을 정리한다. 비동기 콜백은 유효성 및 세션 토큰을 확인한다.
- 실패해도 기존 아르켈론 열람으로 복귀하는 폴백을 제공한다. 기능 플래그 off에서 기존 동작이 유지되어야 한다.

## 8. Opus와 Sonnet의 순차 작업 분담

품질을 위해 Opus가 전체 설계와 최종 통합을 소유한다. Sonnet에게 두루뭉술하게 ‘전체를 알아서 완성’시키지 않는다. 이 분담은 성공 보장이 아니라 이 프로젝트에 권장하는 작업 방식이다.

A. Opus 사전 조사·설계
현재 코드/BP/실제 FBX/Niagara를 열어 위의 미확인 항목을 해결한다. 원본 미리보기, 시계 조립, Android FX 최소 실행을 먼저 검증한다. 문서 design.md에 상태 전이, 입력 소유권, 클래스/API, 파일 소유 범위, 사용자 파라미터 계약, 취소·폴백을 확정한다. 실제 모델을 보지 않은 피벗 수치를 Sonnet에게 넘기지 않는다.

B. Sonnet 작업 1: 시계 임포트·조립
확정 설계대로 재실행 가능한 import script와 파생 에셋, 시계 Actor만 구현한다. 앞·뒤·회전 검수 이미지, 삼각형/텍스처/재질 수 보고. AR/UI 코드는 건드리지 않는다.

C. Sonnet 작업 2: 상태·궤적
Opus가 확정한 API로 상태와 곡선 궤적, 중복 실행·취소·재시도 처리를 구현한다. 핵심 상태 전이에 의미 있는 자동 테스트를 추가한다. 기존 Pawn/Widget 연결이 필요하면 정해진 파일·함수 범위만 변경한다.

D. Opus: Niagara 미술 조정·AR 통합
효과 원본을 직접 비교하고 파생 그래프/재질을 조정한다. mobile preview와 실제 기기에서 색·가림·블러·타이밍을 검수한다. 손 입력, 응시 등장, 정보창, 스캔 종료 간 경합을 해결한다. Sonnet 결과를 검토하고 계약 변경 시 문서를 갱신한다.

E. Sonnet: 확정된 수정·검증 보조
검수에서 나온 수치 조정·패키징 스크립트·회귀 테스트를 제한된 작업으로 수행한다. 새 설계를 독자 도입하거나 다른 작업 파일을 덮어쓰지 않는다.

F. Opus: 최종 품질 승인
에디터 이미지로 완료하지 말고 Android 녹화, 성능, 반복/취소 회귀 결과로 판단한다. 사용자가 봤을 때 ‘시계 투척과 시간 전환’이 즉시 읽혀야 한다.

각 작업 종료 시 handoff.md에 변경 파일, 검증 결과, 실제 캡처, 미해결 항목을 적고 다음 역할이 읽는다. 동시에 같은 uasset/BP를 수정하지 않는다.

## 9. 검증·완료 기준

에디터/자동화:
- 정상 상태 전이, 중복 인식, 연속 스와이프, 재시도, 모든 중간 상태에서 취소, 새 세션 재실행을 검증.
- 누락된 시계/FX 에셋에서도 기존 열람 폴백과 입력 복구가 작동.
- 기존 DinoCard 및 관련 Docent 테스트를 실행. 테스트 이름은 현재 목록에서 확인.
- 참조 없는 문자열 LoadObject만으로 cook 포함을 가정하지 않는다. DataAsset의 명시 참조/검증된 AssetManager 또는 제한된 cook 설정으로 파생 에셋과 의존 텍스처를 포함한다.
- 원본 팩 전체·원본 FBX·4K 텍스처를 불필요하게 패키징하지 않는다.

Android 실기기:
- 실제 AR 마커 인식부터 첫 투척(콜드 실행 포함), 명중, 등장, 정보창 열기와 AR 복귀까지 녹화.
- 밝은 배경과 어두운 배경, 최소 2개 거리에서 시계 문자판·바늘·금색이 읽힘.
- 시계가 고리 중심에 있고 바늘 피벗이 안정적. 문이 모델을 가리는 검은 판이 되지 않음.
- 추적 중단/복구, 연출 중 모드 이탈, 앱 백그라운드/복귀, 반복 10회 후 잔류 효과·입력 잠김·중복 모델 없음.
- 동일 휴대폰에서 기준 AR와 연출 버전의 frame time/메모리를 비교. 목표는 연출 중 30fps 이상(약 33.3ms/frame)이며 미달이면 입자·반투명 오버드로우·텍스처·동시 효과를 줄인다. 평균만 말하지 말고 명중/등장 순간의 끊김과 첫 실행 지연도 기록한다.
- GPU 문제를 desktop 결과로 통과 처리하지 않는다. 에셋 사전 로딩을 비동기로 진행하고 Ready 진입 전 준비를 마쳐 투척 순간 로딩 멈춤을 줄인다.

최종 산출물:
1. 적용 코드 및 파생 에셋, 재현 가능한 임포트/설정 스크립트.
2. 실제 파라미터와 조립 수치를 담은 profile 및 설명.
3. Android APK 경로, build/cook 로그, 실기기 모델·렌더러·성능 측정.
4. 준비/명중/문 확장/등장/완료 5장 캡처와 연속 녹화.
5. 기존 UI 회귀 결과, 알려진 한계, 원복/기능 끄기 방법.

완료 판정은 ‘컴파일됨’이 아니라 실제 휴대폰에서 연출과 기존 기능이 함께 작동함이다. 확인하지 못한 항목은 미검증으로 남기고 성공했다고 보고하지 않는다.
